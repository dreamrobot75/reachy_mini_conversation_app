## 방향 결정 배경

1차 계획(plan_first.md)의 데스크 컴패니언 시나리오는 상당 부분이 공식 conversation_app에
이미 구현되어 있다(대화 루프, 슬립 모션, 얼굴 추적, 감정 모션, 기억, 페르소나).
세 가지 방향을 심사위원 관점에서 비교해 **하이브리드(C)** 로 결정했다.

| 방향 | 판단 |
| :--- | :--- |
| A. 새 시나리오 재기획 | 4.5주·개발 1~2명으로 기존 앱 수준 완성도를 재현 불가. 기획에 시간을 뺏겨 구현 기간 반토막 위험 |
| B. 한국어 개선만 집중 | STT/TTS 품질은 대부분 백엔드 모델 성능이라 팀 기여가 심사에서 안 보임. 개선 표면적도 좁음 (현재 `REALTIME_TRANSCRIPTION_LANGUAGE` 설정 수준) |
| **C. 하이브리드 (채택)** | 기존 앱을 베이스로 **미구현 갭**(DoA·웨이크 워드·상시 대기·한국어 페르소나·데스크 도구)을 완성. 생태계 활용 + 눈에 보이는 차별화 + upstream 기여 세 마리 확보 |

핵심 인식: **시나리오가 이미 구현되어 있다는 건 약점이 아니라 강점.** 오픈소스 공모전에서
심사위원은 재구현보다 "기존 생태계 위에 없던 가치를 얹는 것"을 높게 평가한다.

## 접수서 약속 이행 매핑

심사위원은 접수서와 제출물을 대조한다. 접수한 프로젝트 정보의 약속별 이행 계획:

| 접수서 약속 | 이행 |
| :--- | :--- |
| 음원 방향 추적(DoA) | **본 범위 — W2 최우선** (접수서 명시 항목) |
| 카메라 안면 인식 | 베이스 앱 `head_tracking` 활용 (확보됨) |
| 6-DOF 머리·안테나 감정 표현 | 베이스 앱 모션 + `play_emotion` 활용, **데모에 감정 반응 장면 필수** |
| VAD·STT·LLM·TTS 저지연 파이프라인 | 베이스 앱 제공 (확보됨) + 한국어 튜닝 |
| 일정 브리핑 | **본 범위 — 경량 구현** (로컬 일정 파일/ICS 구독, OAuth 불필요). 정식 캘린더 연동은 2차 |
| 날씨 안내 | 본 범위 — `tools/` 신규 도구 |
| 집중 모드·휴식 알림 (디지털 웰빙) | 본 범위 — 뽀모도로 도구 |
| 문서·코드·**안전 설계** 공개 | W4 산출물 — 안전 설계 문서 (토크 제한·슬립 자세·충돌 대응) |
| 재현·확장 가능한 HRI 레퍼런스 | W4 산출물 — **재현 가이드 + 모듈별 문서** (정식 제출물) |
| OROCA·글로벌 upstream 기여 | upstream 이슈/PR 병행 + 커뮤니티 공유는 2차 기간 |

주의: 접수서에 **웨이크 워드는 명시되지 않았다.** 상시 대기 스토리를 위해 구현하되
우선순위는 DoA보다 낮으며, 실패 시 fallback으로도 접수서 약속은 전부 지켜진다.

## 범위

### In scope (우선순위 순)

1. **음원 방향 추적(DoA)** — reSpeaker 마이크 어레이. **MVP는 웨이크 직후 1회 방향 전환**
   후 기존 `head_tracking`(얼굴 추적)에 인계. 상시 추적은 2차 고도화
2. **상시 대기 상태 머신** — 슬립 → 웨이크업 → 대화 → 수면 복귀 자율 전환.
   `app_lifecycle.py`·`idle_policy.py`에 연결, 기존 `go_to_sleep` 모션 재사용
3. **한국어 데스크 컴패니언 페르소나** — `profiles/` 신규 디렉토리. 한국어 시스템 프롬프트,
   아침 브리핑·집중 모드·취침 인사 멘트. `REALTIME_TRANSCRIPTION_LANGUAGE=ko` 기본값
4. **한국어 웨이크 워드** — 슬립 중 로컬 엔진으로 호출어 감지(예: "레치야").
   엔진은 W3 초 스파이크로 결정(Porcupine 한국어 커스텀 vs openWakeWord 커스텀 학습).
   슬립 중에는 대화 루프가 마이크를 해제하고 웨이크 엔진만 점유.
   **Fallback**: reSpeaker 음성 감지 + DoA로 "큰 소리 방향을 보며 깨어남"
5. **데스크 도구 3종** — 뽀모도로(`tools/` + `background_tool_manager.py` 타이머,
   집중 모드 시 안테나 다운 모션 연동), 날씨(`tools/` 신규, 공개 API),
   **일정 브리핑 경량판**(`tools/` 신규 — 로컬 일정 파일 또는 ICS 구독 URL 읽기)

### Out of scope — 1차에서 의도적 제외 (2차 고도화 백로그로)

- 구글 캘린더 정식 연동(OAuth/MCP) — 경량판으로 약속 이행 후 2차에서 고도화
- 착석 감지·부재 시 자동 슬립, 상시 DoA 추적
- 감정 인식 고도화(사용자 표정·톤 반응) — 1차의 "감정 반응"은 LLM 주도 `play_emotion`으로 표현
- 새 모션 대량 제작 — 기존 감정 모션·댄스 재사용

### Upstream 기여 병행

일반화 가능한 두 가지를 upstream에 이슈 → PR로 제출 (머지 여부와 무관하게 기여 증빙):

- (a) 웨이크 워드 훅 — 슬립 중 외부 웨이크 트리거 인터페이스
- (b) 언어/로케일 설정 확장

우리 저장소는 fork로 유지하며 자유롭게 개발한다.
(실무 선행 작업: GitHub fork 생성 후 origin을 fork로, upstream을 공식 저장소로 재설정)

## 아키텍처 매핑

| 기능 | 구현 위치 |
| :--- | :--- |
| 상태 머신 | `app_lifecycle.py` / `idle_policy.py` 확장 |
| DoA | `audio/` 신규 모듈 (reSpeaker 의존 → mock 인터페이스 필수) |
| 웨이크 워드 | `audio/` 신규 모듈 + 상태 머신 연동 (LLM 도구 아님 — 자율 동작) |
| 웨이크 방향 전환 | `moves.py` + `tools/head_tracking.py` 인계 |
| 페르소나 | `profiles/` 신규 디렉토리 + `config.py` 언어 기본값 |
| 뽀모도로 | `tools/` 신규 `Tool` + `background_tool_manager.py` |
| 날씨 / 일정 브리핑 | `tools/` 신규 `Tool` 각 1개 |

- LLM이 호출하는 기능은 `Tool` 서브클래스 (파일 1개 = 도구 1개, 실패 시 `{"error": ...}`)
- LLM 개입 없는 자율 기능(DoA·웨이크 워드)은 상태 머신에 연결되는 모듈
- 새 설정값은 `config.py` + `.env.example`

## 2차 평가 고도화 백로그 (9월 ~ 10월, 1차 통과 시)

우선순위는 1차 심사 피드백 반영 후 재조정한다:

- 구글 캘린더 정식 연동 (OAuth 또는 MCP 경유)
- 상시 DoA 추적 (대화 중 화자 방향 실시간 추종)
- 착석 감지 + 부재 시 자동 슬립 (접수서 "안전 설계" 서사 강화)
- 감정 인식 고도화 — 사용자 표정·목소리 톤에 반응하는 감정 표현
- upstream PR 머지 후속 작업 (리뷰 대응)
- OROCA 커뮤니티 튜토리얼·발표 자료 (학습 교재 서사 완성)

## 데모 영상 스토리 (2~3분)

1. 슬립 중인 로봇 (고개 숙임, 안테나 다운) → "레치야" 호출
2. **소리 방향으로 고개를 돌리며** 기지개 웨이크업 → 시선 고정 *(차별화 #1 — DoA)*
3. 한국어 아침 브리핑 — **오늘 일정 + 날씨** + 인사 *(차별화 #2 — 접수서 약속 이행)*
4. 대화 중 **감정 반응 장면** — 칭찬에 기뻐하는 안테나·머리 모션 *(차별화 #3 — 프로젝트명 "감정 반응형" 입증)*
5. "집중 모드 시작해줘" → 뽀모도로 + 안테나 다운 집중 자세 *(차별화 #4)*
6. "잘 자" → 취침 인사 후 슬립 복귀
7. 마지막 30초: 아키텍처 다이어그램 + 재현 가이드·안전 설계 문서 + upstream 기여(PR 링크)
