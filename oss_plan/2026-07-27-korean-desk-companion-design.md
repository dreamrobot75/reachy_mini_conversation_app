# 한국어 상시 대기 데스크 컴패니언 — 공모전 설계서

- **날짜**: 2026-07-27
- **상태**: 설계 승인됨 (구현 계획 수립 전)
- **선행 문서**: [plan_first.md](plan_first.md) (1차 시나리오 기획)

## 한 줄 정의

> 공식 `reachy_mini_conversation_app`을 **'켜고 말하는 도구'에서 '책상 위에 상주하며
> 부르면 돌아보는 한국어 동반자'로 확장**한다.

## 방향 결정 배경

1차 계획(plan_first.md)의 데스크 컴패니언 시나리오는 상당 부분이 공식 conversation_app에
이미 구현되어 있다(대화 루프, 슬립 모션, 얼굴 추적, 감정 모션, 기억, 페르소나).
세 가지 방향을 심사위원 관점에서 비교해 **하이브리드(C)** 로 결정했다.

| 방향 | 판단 |
| :--- | :--- |
| A. 새 시나리오 재기획 | 1개월·개발 1~2명으로 기존 앱 수준 완성도를 재현 불가. 기획에 시간을 뺏겨 구현 기간 반토막 위험 |
| B. 한국어 개선만 집중 | STT/TTS 품질은 대부분 백엔드 모델 성능이라 팀 기여가 심사에서 안 보임. 개선 표면적도 좁음 (현재 `REALTIME_TRANSCRIPTION_LANGUAGE` 설정 수준) |
| **C. 하이브리드 (채택)** | 기존 앱을 베이스로 **미구현 갭**(웨이크 워드·DoA·상시 대기·한국어 페르소나·데스크 도구)을 완성. 생태계 활용 + 눈에 보이는 차별화 + upstream 기여 세 마리 확보 |

핵심 인식: **시나리오가 이미 구현되어 있다는 건 약점이 아니라 강점.** 오픈소스 공모전에서
심사위원은 재구현보다 "기존 생태계 위에 없던 가치를 얹는 것"을 높게 평가한다.

### 제약 조건

- 심사 기준 미공지 → 일반 기준(창의성·완성도·기여도) 모두 방어하는 전략
- 마감 1개월 이내, 실질 개발 인원 1~2명
- 실물 Reachy Mini 보유, 제출물은 **데모 영상 + 코드**

## 범위

### In scope (우선순위 순)

1. **상시 대기 상태 머신** — 슬립 → 웨이크업 → 대화 → 수면 복귀 자율 전환.
   `app_lifecycle.py`·`idle_policy.py`에 연결, 기존 `go_to_sleep` 모션 재사용
2. **한국어 웨이크 워드** — 슬립 중 로컬 엔진으로 호출어 감지(예: "레치야").
   엔진은 W2 초 스파이크로 결정(Porcupine 한국어 커스텀 vs openWakeWord 커스텀 학습).
   슬립 중에는 대화 루프가 마이크를 해제하고 웨이크 엔진만 점유
3. **음원 방향 추적(DoA)** — reSpeaker 마이크 어레이. **MVP는 웨이크 직후 1회 방향 전환**
   후 기존 `head_tracking`(얼굴 추적)에 인계. 상시 추적은 stretch
4. **한국어 데스크 컴패니언 페르소나** — `profiles/` 신규 디렉토리. 한국어 시스템 프롬프트,
   아침 브리핑·집중 모드·취침 인사 멘트. `REALTIME_TRANSCRIPTION_LANGUAGE=ko` 기본값
5. **데스크 도구 2종** — 뽀모도로(`tools/` + `background_tool_manager.py` 타이머,
   집중 모드 시 안테나 다운 모션 연동), 날씨(`tools/` 신규, 공개 API)

### Out of scope (의도적 제외)

- 착석 감지, 감정 인식 고도화 — 1개월 내 품질 보장 불가
- 구글 캘린더 — OAuth 부담 대비 데모 효과 낮음. stretch goal (MCP 경유 가능성만 열어둠)
- 새 모션 대량 제작 — 기존 감정 모션·댄스 재사용

### Upstream 기여 병행

일반화 가능한 두 가지를 upstream에 이슈 → PR로 제출 (머지 여부와 무관하게 기여 증빙):

- (a) 웨이크 워드 훅 — 슬립 중 외부 웨이크 트리거 인터페이스
- (b) 언어/로케일 설정 확장

우리 저장소는 fork로 유지하며 자유롭게 개발한다.

## 아키텍처 매핑

| 기능 | 구현 위치 |
| :--- | :--- |
| 상태 머신 | `app_lifecycle.py` / `idle_policy.py` 확장 |
| 웨이크 워드 | `audio/` 신규 모듈 + 상태 머신 연동 (LLM 도구 아님 — 자율 동작) |
| DoA | `audio/` 신규 모듈 (reSpeaker 의존 → mock 인터페이스 필수) |
| 웨이크 방향 전환 | `moves.py` + `tools/head_tracking.py` 인계 |
| 페르소나 | `profiles/` 신규 디렉토리 + `config.py` 언어 기본값 |
| 뽀모도로 | `tools/` 신규 `Tool` + `background_tool_manager.py` |
| 날씨 | `tools/` 신규 `Tool` |

- LLM이 호출하는 기능은 `Tool` 서브클래스 (파일 1개 = 도구 1개, 실패 시 `{"error": ...}`)
- LLM 개입 없는 자율 기능(웨이크 워드·DoA)은 상태 머신에 연결되는 모듈
- 새 설정값은 `config.py` + `.env.example`

## 4주 마일스톤

| 주차 | 목표 | 산출물 |
| :--- | :--- | :--- |
| **W1** | 빠른 승리 + 뼈대 | 한국어 페르소나, `ko` 전사 기본값, 상태 머신 뼈대(수동 웨이크 트리거), 데모 대본 초안 |
| **W2** | 차별화 ① | 웨이크 워드 스파이크(2일 내 엔진 결정) → 통합, 뽀모도로 + 안테나 모션 |
| **W3** | 차별화 ② + 기여 | DoA 웨이크 방향 전환, 날씨 도구, upstream 이슈/PR, 통합 안정화 |
| **W4** | 제출물 | 데모 영상 촬영·편집, README 정비(아키텍처·기여 내역), 버퍼 |

**원칙: 매주 끝에 데모 가능한 상태 유지.** W1 종료 시점에 이미 "한국어 대화 컴패니언"이
시연 가능하고, 이후 매주 차별화 기능이 하나씩 얹힌다.

## 데모 영상 스토리 (2~3분)

1. 슬립 중인 로봇 (고개 숙임, 안테나 다운) → "레치야" 호출
2. **소리 방향으로 고개를 돌리며** 기지개 웨이크업 → 시선 고정 *(차별화 #1)*
3. 한국어 아침 브리핑 — 날씨 + 인사 *(차별화 #2)*
4. "집중 모드 시작해줘" → 뽀모도로 + 안테나 다운 집중 자세 *(차별화 #3)*
5. "잘 자" → 취침 인사 후 슬립 복귀
6. 마지막 30초: 아키텍처 다이어그램 + upstream 기여(PR 링크)

## 리스크와 안전장치

| 리스크 | 안전장치 |
| :--- | :--- |
| DoA 품질 미달 | 웨이크 시 얼굴 추적(`head_tracking`)으로 방향 잡는 fallback — 데모 스토리 유지 |
| 웨이크 워드 오인식 | 데모 환경 감도 튜닝. W2 스파이크에서 조기 판단 → 최악엔 대화 루프 내 이름 호출로 전환 |
| 마이크 자원 경합 | 슬립 진입 시 대화 루프의 마이크 해제를 상태 머신 전이 조건으로 설계 |
| 인원 이탈 | W1 산출물만으로 최소 스토리(한국어 컴패니언 + 수동 웨이크) 제출 가능 |

## 테스트

- 도구(뽀모도로·날씨): 기존 `tests/` 패턴의 happy-path 단위 테스트, `{"error": ...}` 반환 검증
- 상태 머신: 전이 로직 단위 테스트 (하드웨어 mock)
- 웨이크 워드·DoA: mock 인터페이스 + 실기 체크리스트 (자동 테스트 제외 — 하드웨어 의존)
- 기존 CI 게이트(ruff/mypy/pytest) 통과 유지 — upstream PR 병행에 필수
