## 배경과 결정

W2 시작 시점(8/4)에 기능 축이 설계서 대비 1~2주 선행됐다. 구현 완료:
한국어 음성 베이스라인(`desk_companion_ko`), standby 상태 머신(transcript 웨이크),
DoA 소리 방향 시선, 뽀모도로(백그라운드 태스크 + standby 완료 알림), 종료 시 슬립,
데몬 연결 env·자동 기동. 날씨는 HF Tool Space
(`pollen_robotics_reachy_mini_weather_tool`)로 해결됐다.

남은 3주의 방향을 세 가지로 비교해 **A. 제출물 역산 투트랙**으로 결정했다:

| 방향 | 판단 |
| :--- | :--- |
| **A. 제출물 역산 투트랙 (채택)** | 심사위원이 실제로 보는 것은 영상+문서. 선행분을 제출물 품질·약속 완결·기여 증빙에 투입해 창의성·완성도·기여도 세 축을 모두 방어 |
| B. 신규 기능 베팅 (2차 백로그 조기 착수) | "범위 확장 유혹 금지" 원칙 위반. 하드웨어 의존 기능은 3주 내 안정화 어려워 데모 실패 리스크가 완성도를 깎음. 재료는 2차 고도화 기간(9~10월)에 사용 |
| C. 안정화 올인 (기능 동결) | 일정 브리핑(접수서 약속) 불이행으로 남음. 2명 리소스 대비 일이 남음 |

추가 결정:

- **일정 브리핑**: 미구현 확인 → 경량판을 이번에 구현한다 (유일한 신규 기능).
- **웨이크 워드 로컬 엔진**: 스파이크하지 않는다. 현행 transcript 기반 웨이크로 충분하며,
  그 시간을 제출물에 투입한다.

## 일정 브리핑 경량판 설계

- **위치**: `src/reachy_mini_conversation_app/tools/` 신규 `Tool` 서브클래스 1개
  (파일 1개 = 도구 1개). 도구 이름 예: `daily_schedule`.
- **데이터 소스**: `icalendar` 파싱으로 **로컬 `.ics` 파일 + 구글 캘린더 비공개 ICS 구독
  URL** 둘 다 지원. OAuth 없이 "진짜 내 일정" 브리핑 데모가 가능해 로컬 JSON보다 서사가
  강하다. 정식 캘린더 연동(OAuth/MCP)은 2차 백로그 유지.
- **설정**: `config.py` + `.env.example`에 ICS URL 또는 파일 경로 설정 추가
  (예: `SCHEDULE_ICS_URL` / `SCHEDULE_ICS_PATH`).
- **반환**: 오늘/요청 날짜의 일정 목록 dict. 실패(파일 없음, URL 오류, 파싱 실패) 시
  raise 대신 `{"error": ...}` 반환 — 대화 루프를 죽이지 않는다.
- **프로필 연동**: `desk_companion_ko`에 도구 등록 + 아침 브리핑 지침 추가.
  날씨 도구와 묶어 "오늘 일정 + 날씨" 브리핑 → 데모 3번 장면 완성.
- **테스트**: 고정 ICS fixture 파싱 happy-path + 에러 반환 검증 (기존 `tests/` 패턴).
- **축소 경로**: 지연 시 ICS URL 지원을 빼고 로컬 `.ics` 파일만으로 축소해도
  접수서 약속("일정 브리핑")은 이행된다.
